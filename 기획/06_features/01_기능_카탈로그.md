## 회의 반영 기능 변경 (핵심 — 본 박스가 최신 등급)

### MVP (M1) 로 승격된 것
- **U-09 OAuth 로그인** (Google) — 회의에서 MUST
- **U-10 이메일 화이트리스트** — MUST
- **U-11 realName / major 입력** + 보완 페이지 리다이렉트 — MUST
- **P-11 linkedRequestId 자동 완료** — MUST. 요청 게시판 핵심 흐름
- **F (통합 File 도메인)** F-01~F-04 통합. MUST
- **R-09 자동 COMPLETED** (게시글에 linkedRequestId 박으면) — MUST

### M2 로 미뤄지거나 v1.1로 보류
- U-09 OAuth Naver — M2 (Google 먼저)
- F-03 DownloadLog / F-05 top-files / 통계 — **v1.1**
- 어드민 게시글 강제 삭제, 유저 제재 / 강제 삭제 — **본 MVP 범위 외**
- 어드민 메시지 강제 열람 — **본 MVP 범위 외**
- 카카오 OAuth — **본 MVP 범위 외**

### 제거된 것 (기능 자체가 사라짐)
- 비회원 익명 다운로드 — 회원만 가능 (저작권 정책)
- 익명 피드백 — 로그인 필수
- Request `/review` 단계 어드민 검토 — 본 MVP는 REQUESTED → IN_PROGRESS 직행
- Request `/link-post` 별도 엔드포인트 — Post 작성 시 자동 처리로 흡수

> 아래 본문의 옛 MoSCoW 표와 충돌 시 본 박스 우선.


> 비유: **레스토랑 메뉴판.** 핵심 메뉴(MUST)는 무조건 내야 하고, 사이드(SHOULD)는 가능하면, 디저트(COULD)는 여유 있을 때, 시그니처(WON'T-this-time)는 다음 시즌.

## 우선순위 기준 (MoSCoW)

| 등급 | 의미 | 본 프로젝트의 의미 |
|---|---|---|
| **MUST** | 없으면 서비스 자체가 안 됨 | **M1(6/1)** 까지 무조건 완료 |
| **SHOULD** | 있어야 정상적 사용성 | **M2(6/9)** 까지 완료 = TA반 배포 시점 |
| **COULD** | 있으면 좋음 | M3(6/16)에 시도, 안되면 v1.1 |
| **WON'T (this release)** | 이번 한 달엔 안 함 | v1.1 백로그 |

## 인수 기준 (Acceptance Criteria) — 핵심만

### P-01 게시글 작성 AC
- [ ] 비인증 401
- [ ] 제목/본문 누락 시 400 + 필드 정보
- [ ] 확장자 불일치 시 400 `FILE_EXTENSION_NOT_ALLOWED`
- [ ] 합계 20MB 초과 시 400 `FILE_TOO_LARGE`
- [ ] 카테고리 미존재 시 404 `CATEGORY_NOT_FOUND`
- [ ] 성공 시 PostResponse 반환, 응답에 files[]·tags[]·teamId 포함
- [ ] 트랜잭션: File 저장 도중 실패 시 디스크에 남은 파일은 cleanup (compensating)

### R-04 상태 전이 AC
- [ ] 허용된 전이만 가능 (표 별도). 아니면 400 `REQUEST_STATUS_TRANSITION_INVALID`
- [ ] 일반 USER는 REQUESTED → 수정/취소만, IN_REVIEW부터는 ADMIN/assignee만
- [ ] 전이 성공 시 알림 DM (시스템 발신자)
- [ ] COMPLETED 전이는 `linked_post_id` 가 있어야만 (또는 link-post 와 함께)

### D-01 메시지 송신 AC
- [ ] 자기 자신에게 보낼 시 400 `MESSAGE_SELF_NOT_ALLOWED`
- [ ] 수신자 미존재 시 404
- [ ] 성공 시 WS 푸시 (`/user/queue/messages`) + REST 응답
- [ ] 송신 직후 수신자의 `unread` 가 1 증가

전체 AC는 각 파트 가이드(`07_part_guides/`)에 더 상세히 적혀 있습니다.
